# DigitalMask exports

`buildExport(input): Promise<{ bytes: Uint8Array; mime: string; filename: string }>` creates a complete download in memory. The caller authorizes and filters records and members; `references` contains authorized lookup records, and `images` contains already downloaded private image bytes keyed by file ID. This module never queries a database or downloads remote assets.

`selectExportRecords({ kind, records, teamOnly?, productionId?, userIds? })` is the shared in-memory selector used before private asset loading and again by `buildExport`. `teamOnly: true` exports only tasks without a production; it cannot be combined with `productionId` or another kind. Production filters select an exact production or its associated records. Teamboard downloads have their own filename and report title. `userIds: string[]` selects calendar participants or owners of time/attendance records, after caller authorization. An explicit empty array selects no calendars; omitting the filter selects all authorized calendars. The API preserves this distinction with `userIds=` versus an omitted parameter.

Production contacts resolve internal makeup contacts against authorized members, while external names remain text. CSV/XLSX/PDF include readable roles, names and contact types. JSON keeps the original contact data and adds a resolved `contactDirectory` alongside it. Casting and character PDFs append captioned private image galleries; photo bytes are supplied by the caller and normalized locally just like look images.

External production contacts can link an authorized `references.people` profile. The current directory name, organisation, position, email, telephone and notes take precedence over the contact snapshot. `kind: "people"` provides a separate contact directory in PDF/XLSX/CSV/JSON without creating accounts. Casting resolves current actor/character references first, then free-text names; unavailable references display a readable placeholder instead of IDs.

Look documents use the actor's name as title, the production's duration (or its document override), and structured repeatable entries in Preparation/Makeup/Hair/Wigs and Beards/Changeovers/Setup. Custom and renamed categories resolve against `references.categories`; CSV/XLSX include separate dynamically named section columns. Handovers are global documents with care/notes/custom sections and individual checklist elements, without production/status/performance-date columns. Both PDF document types preserve all supplied private images. Legacy fields and template values are converted in memory by the shared `documentSections` helper; old scene/time information is explicitly printed in historical notes. `documentPresentation(record,input)` supplies a readable sidecar while original JSON remains intact.

Printed PDF/XLSX headers identify an optional selected `year` or `season` in addition to date ranges. Selection is performed by the caller/shared selector; presentation does not fetch or requery any records.

- **PDF:** A4 landscape month/week/team grids and a full agenda supplement; portrait day/agenda reports; dedicated structured look sheets with photographs; readable repeating table headers and exact page counts. Long cells continue on further rows/pages. Bundled Noto Sans regular/bold fonts use the included SIL Open Font License. Stored WEBP images are normalized locally. Table reports and look sheets print all supplied content; a missing image is explicitly identified.
- **XLSX:** Actual Excel tables, frozen headings, filters, wrapped text, typed Berlin wall-clock dates, elapsed-hour number formats and person/project totals. Long cells use continuation rows so print height limits do not silently hide notes. Wide look tables span horizontal pages and repeat identity columns.
- **CSV:** UTF-8 BOM, German semicolon delimiter, quoted multiline fields, escaped quotes and protection against formula injection.
- **ICS:** RFC 5545 escaping, CRLF and UTF-8-aware 75-octet folding, stable UIDs, UTC timestamps and local Europe/Berlin recurrence definitions with DST transitions, until dates and exceptions. This is a calendar export/subscription format.
- **JSON:** Versioned original record data, retaining IDs, versions and full structured fields. Lookup records and member/session data are not implicitly included; binary files remain in private storage and require a separate file backup.

Recurring events expand only in the selected print/report range. Calendar exports allow at most two years and 20,000 occurrences. Time reports use trusted server-computed `dayAllocations: [{ date, seconds }]` when present: only days inside the export window count, and their sum must match the original duration. JSON retains the unsplit booking. The caller must select bookings by overlapping allocation dates, rather than start date alone.

`kind: "attendance"` is a separate report, never a production-hours category. PDF and XLSX include person, local-day and ISO-week summaries; JSON retains original bookings alongside a selected-window `attendanceSummary` in integer seconds. CSV contains the detailed local-day allocations. Historical employee names remain available in these reports even if the account is inactive. The same trusted allocation validation applies to attendance across midnight or a DST change.

Calendar UI parameters are `view: "month" | "week" | "day" | "agenda" | "team" | "team-month"`, `from`/`to` inclusive `YYYY-MM-DD`, and optional `userIds`. For `team-month`, pass the month's first and last day. PDF divides the month into seven-day blocks and staff groups with repeated person/day headers, followed by a complete agenda and a category legend. XLSX creates one seven-day worksheet per week with frozen identity columns, complete titles and continuation rows, plus its detailed data table and legend. Staff grids show active non-superadmin members; an unassigned row appears when applicable.

Supply current authorized `references.calendarCategories` and `references.productions`. All calendar formats resolve an empty event title to the current production name, then category name, without changing stored data. Category names/colors/all-day defaults use the shared presentation helper. Ganztägig entries print dates without clock times; human end dates are inclusive, ICS `DTEND;VALUE=DATE` is exclusive. Recurrence preserves local start/end clock times and local-day spans over DST, including 23/25-hour all-day occurrences.

Run `npx vitest run tests/exports.test.ts` for data and PDF extraction checks. Run `npx tsx scripts/verify-exports.ts`, or set `EXPORT_RENDER_QA=1` and run `npx vitest run tests/exports-render.test.ts`, to generate fictional PDFs and every page raster in ignored `artifacts/exports/`. The raster suite validates media boxes, final text markers and page counters. Inspect these PNGs after changing layouts. Runtime requires Node.js and tracing `src/modules/exports/assets/**/*` into the deployment.

`tests/exports-productions.test.ts` verifies contact resolution, Teamboard/project separation, long-role page breaks and casting/character images. Set `EXPORT_RENDER_QA=1` for focused fictional production-contact and two-image gallery PDF/PNG fixtures without rerendering the original calendar suite.

`tests/exports-attendance-calendar.test.ts` verifies attendance separation/day allocations/summaries, selected users, dynamic calendar categories, RFC all-day recurrence, DST endpoints, weekly XLSX grids and a 31-day/13-person multipage PDF fixture. With `EXPORT_RENDER_QA=1`, only fictional PDFs, every page PNG and contact sheets are saved in a newly created `digitalmask-attendance-calendar-*` directory under the system temporary folder. Inspect the PNGs after calendar/attendance layout changes.

`tests/exports-documents.test.ts` checks current contact profiles, free-text casting, dynamic document sections, copyable spreadsheet contact fields, legacy text/template preservation, global checklists, category names, complete long PDF entries and multiple private pictures. `EXPORT_RENDER_QA=1` saves its synthetic PDFs and page PNGs in a new `digitalmask-document-exports-*` system temporary directory for visual inspection.
